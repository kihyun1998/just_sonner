(`8e4662b39255120b62138312058f5d77c0139a5e`, 2026-08-10, "Update README.md (#778)").
Files fetched raw through the GitHub contents API at that SHA: `src/index.tsx`, `src/state.ts`,

## Short answer

- **Every cited number matches**: 356, 14, 24 / 16, 3, 4000 ms, `1 − 0.05 × i`, `gap × i`,
  400 ms transform/opacity/height, `TIME_BEFORE_UNMOUNT` 200, 45 px, 0.11 px/ms,
  `getDefaultSwipeDirections`, the dismissed-id rule in `state.ts`, and the three pause conditions.
- **Toasts beyond `visibleToasts` do count down in sonner.** Every toast in the list is mounted as
  a `<Toast>` and runs the same timer effect. Nothing in it checks `isVisible`. A hidden toast is
  only `opacity: 0; pointer-events: none` and can expire before it is ever seen. That answers
  spec §11 Q3 as far as sonner goes.
- **Where the spec differs or leaves something out** (details in the table): swipe-out 200 ms is
  sonner's value, not just_sonner's. Sonner's "interacting" pause starts on *any* pointer-down in
  the toaster, not only a drag. `document.hidden` is narrower than "not `resumed`". Sonner also
  blocks swipe (and the close button) on `loading` toasts. An update restarts a running timer. The
  dismissed-id rule only holds in `state.ts`: the render layer still merges into a toast with that
  id that is mid-exit. `width` is not a sonner prop. In sonner a duration of `0` means the default,
  and `Infinity` means it stays.

## Differences, collected

1. **Swipe-out 200 ms** (§6 Motion) is attributed to just_sonner, but it is sonner's
   (`styles.css` L359-L364, ease-out). *(row 12)*
2. **Swipe on `loading`** (§8): sonner also disables swipe on `loading` toasts and does not render
   the close button for them. The spec names only `dismissible: false`. *(row 17)*
3. **"Being dragged" pause** (§7): sonner's `interacting` is any pointer-down inside the toaster
   until pointer-up, so a press on a button pauses too. *(row 23)*
4. **App-hidden pause** (§7): sonner uses `document.hidden`. "Not `AppLifecycleState.resumed`" also
   pauses on focus loss (`inactive`), which sonner does not. *(row 24)*
5. **Dismissed-id rule** (§4): true in `state.ts`. Sonner's render layer still merges a re-create
   into a toast with that id that is mid-exit (read, not run), and a dismiss followed by a create
   in the same frame is an update. just_sonner's single controller can make the rule hold
   everywhere, but it has to be stated and tested. *(row 19)*
6. **Timer on update** (not in the spec): sonner restarts a counting toast's timer on any update.
   *(row 21)*
7. **`duration` 0** (§4): sonner treats `0` as "use the default" and uses `Infinity` for
   persistent. The spec's `Duration.zero` = persistent is a deliberate difference from sonner. It is
   worth marking as such. *(row 5)*
8. **`width`** is not a sonner prop: it is hard-coded and overridable only through CSS. The value
   matches. *(row 1)*

Minor, value matches: `TIME_BEFORE_UNMOUNT` claims to equal the exit animation, but the exit CSS
transitions are 400 ms or 500 ms and get cut off at 200 ms (row 11). The scale formula only reads
as `1 − 0.05·i` once CSS token substitution is applied (row 6). The mobile offset applies below a
600 px viewport (row 3).
